Polymarket
Sentinel

A paper-first trading desk for Polymarket's five-minute BTC markets. Seven async agents split the work; the live path arms only through an explicit human switch.

  • RoleDesign & build
  • Scope7 agents, dashboard, overlay
  • StatusPrivate / paper-first

01The problem

Five-minute markets reset constantly. Judgment has to survive the reset.

Polymarket's short-horizon BTC markets open and close all day. Each window is a fresh question with a deadline measured in minutes, and the data that matters — price, momentum, order book — moves faster than a person can watch it.

A model can look sharp on win rate while still losing to fees, spread and the cost of being wrong at the wrong minute. Speed without a risk boundary is not a desk; it is a slot machine with better charts.

02Seven agents, one desk

Separated work. One shared picture.

The system is not one large loop. Seven async agents own one job each and communicate through shared state, so a failure in discovery cannot silently become an order.

  • 01

    Data

    Streams price and market context into a consistent frame.

  • 02

    Signals

    Turns indicators into a probability, not a verdict.

  • 03

    Discovery

    Finds the active window and its tradable strikes.

  • 04

    Risk

    Applies limits, exposure and the single order gate.

  • 05

    Exits

    Watches the position and closes on its own rules.

  • 06

    Execution

    Routes approved orders to paper or live, never both.

  • 07

    Reporting

    Records fills, edge and outcome per window.

  • Human

    Owner switch

    Arms or disarms the live path. Paper is always on.

03The risk gate

One choke point. Nothing routes around it.

New orders pass one risk gate before execution. The gate can refuse an order but cannot create one. The live path stays disarmed until a human flips the switch, and the switch is deliberately boring to use — no shortcut from a promising chart to a real position.

  1. Discover

    The active five-minute window and its strikes are identified.

  2. Score

    Signals produce a probability for the window's outcome.

  3. Risk gate

    Limits, exposure and edge must all clear before an order exists.

  4. Route

    Paper by default. Live only when the owner has armed it.

Win rate is not edge. The read-only dashboard and browser overlay keep both numbers in view — the model's confidence and what the outcome actually paid — so a good-looking call never hides a bad fill.

04How it works

Paper first. Evidence in view.

01

One event loop

asyncio fans out data, signals and exits. Agents read and write shared state instead of calling each other in a chain.

02

Paper by default

Every order fills against a paper book first. The live path is a separate route that requires the owner's switch.

03

Two numbers, always

The dashboard and a Chrome MV3 overlay show edge and win rate side by side before anything is clicked.

What the backtest actually said. Over 30 days and 8,626 market windows, calls at or above 70% confidence scored 80–93% by entry minute. That is a calibration result, not a promise of profit — which is exactly why the overlay keeps edge and win rate in the same frame.

05Stack & status

Built to be stopped.

Python and asyncio carry the agent loop, pandas-ta handles the signal layer, SQLite stores every window and fill, and the CLOB client handles market data and routing. The overlay is a small Chrome MV3 extension — visible, read-only, and easy to close.
